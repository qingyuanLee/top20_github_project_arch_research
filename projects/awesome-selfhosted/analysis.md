- [ ] 一、项目回顾
  - [ ] 1. 一句话结论
    - [ ] 自由软件自托管目录，把数千条目做成"内容即数据"的多仓库工程体系，靠5条CI自动保鲜
  - [ ] 2. 场景问题（3个）
    - [ ] 独立开发者从SaaS迁自托管：按业务域预分类+统一schema，30分钟筛出2-3个可部署方案
    - [ ] Homelab玩家拼家庭服务栈：约95个三级MECE分类，2小时拼完整栈并看清技术栈标签
    - [ ] 企业架构师做合规选型：每条目带SPDX license标签+non-free分册+反特征⚠，合规评审从数天压到数小时
  - [ ] 3. 组成结构（5项）
    - [ ] 主仓库极薄：README.md(2361行)+non-free.md+贡献模板，仅作门面
    - [ ] 内容数据库在姊妹仓库awesome-selfhosted-data：software/一项目一YAML
    - [ ] tags/定义分类层级，platforms/定义技术栈词表，licenses.yml为SPDX注册表
    - [ ] hecat 1.6.0构建器把YAML渲染成Markdown+HTML双产物
    - [ ] 一级按业务域，二级用-做MECE细分，三级约95个###类目
  - [ ] 4. 技术组件（5项）
    - [ ] hecat构建器（Makefile锁定@1.6.0）+ awesome-lint语法校验
    - [ ] 条目schema内置活跃度元数据：stargazers/updated_at/archived/current_release/commit_history月度直方图
    - [ ] 5条CI：pull-request lint / 死链检测 / 失维项目检测 / 每日元数据回写 / 合并重建
    - [ ] 许可证治理：本列表CC-BY-SA-3.0，收录对象必须自由软件，非自由分流non-free.md
    - [ ] 贡献流：改YAML→PR lint→合并build→daily自动保鲜
  - [ ] 5. 验证：stars=319966
- [ ] 二、知识沉淀
  - [ ] 1. 前10优越点
    - [ ] 第1组（结构与工程化）
      - [ ] 优越1：巨型Markdown重构为内容即数据多仓库，数千条目拆YAML，diff干净可并行PR
      - [ ] 优越2：hecat专用构建器+产物双发（Markdown门面+可筛选HTML站），数据层支持二次开发
      - [ ] 优越3：条目schema内置活跃度元数据，读者直接量化判断项目死活
      - [ ] 优越4：5级CI流水线实现免人工保鲜，死链/失维/过期star全部自动发现回写
      - [ ] 优越5：MECE三级分类法（如Communication-Email-MTA），互斥穷尽检索精度高
    - [ ] 第2组（治理与体验）
      - [ ] 优越6：license一等公民+内置SPDX词典+non-free分册，把AGPL传染性做成筛选维度
      - [ ] 优越7：⚠反特征显式标注依赖外部专有服务，守卫"数据在自己手里"第一性原理
      - [ ] 优越8："alternative to X"锚点式描述，直接映射用户已知商业SaaS心智
      - [ ] 优越9：技术栈标签化（Go/Docker/K8S），支持按部署约束筛选
      - [ ] 优越10：贡献入口与门面解耦，star仓库只读稳定，数据PR进data仓库，治理噪音可控
  - [ ] 2. 前10优化点
    - [ ] 第1组（产品与体验）
      - [ ] 优化1：缺官方在线可交互筛选器，第三方前端吃数据，官方HTML站未成主入口
      - [ ] 优化2：活跃度元数据有采集无展示，README条目看不到🟢🟡🔴徽章或活跃度排序
      - [ ] 优化3：全英文无官方i18n，结构化数据天然适合机器翻译但未做
      - [ ] 优化4：同类软件替代/重复关系未建模，缺选型决策树与对比表
      - [ ] 优化5：缺部署难度/资源占用字段（difficulty/min_ram/docker_ready/requires_db）
