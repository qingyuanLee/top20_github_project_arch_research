- [ ] 二、知识沉淀
  - [ ] 1. 前10优越点（第1组：内容工程与自动化）
    - [ ] 优越点1：内容即代码（Markdown in Git），有历史可review可PR，会写md就能贡献
    - [ ] 优越点2：双向同步脚本化，仓库与数据库保持单一事实源，发布可重复可审计
    - [ ] 优越点3：Markdown↔HTML双向转换工程化（markdown-it正向+turndown反向），编辑后回写仓库成为可能
    - [ ] 优越点4：CI全自动发布流水线，合并PR后自动入库+自动清CDN缓存，GitOps式无人值守
    - [ ] 优越点5：孤儿内容自动清理（cleanup-orphaned-content），避免仓库/数据库膨胀与死链
  - [ ] 1. 前10优越点（第2组：规模与贡献）
    - [ ] 优越点6：80+路线图规模化内容矩阵，覆盖前端到云、语言到管理岗完整职业地图
    - [ ] 优越点7：结构化贡献协议分流——改错别字快通道、增删节点先issue，保护内容一致性
    - [ ] 优越点8：draw.roadmap.sh在线编辑器出图，非技术贡献者画完图即可提交，降低创作门槛
    - [ ] 优越点9：内容原则"求新不求全"，倒逼定期淘汰过时节点，保持时效性
    - [ ] 优越点10：slug化URL规范化（slugger.ts），链接可预测可分享不因标题微调失效
  - [ ] 2. 前10优化点（第1组：可观测与质量）
    - [ ] 优化点1：内容与网站代码分离、跨仓依赖不透明，建议README标注网站仓库/DB schema/接口契约
    - [ ] 优化点2：同步脚本缺可见失败告警，建议加失败通知（Slack/自动开issue）与dry-run预览
    - [ ] 优化点3：内容质量无自动化校验，建议CI校验每节点标题/详解齐全、外链存活、必填字段
    - [ ] 优化点4：路线图版本/时间戳未显式标注，建议头部渲染"最后更新日期"结合Git历史生成
    - [ ] 优化点5：单向学习缺进度/自评机制，建议节点加可勾选状态并本地/账号持久化
  - [ ] 2. 前10优化点（第2组：保真与易用）
    - [ ] 优化点6：Turndown反向转换保真度风险，建议补fixture测试与人工diff评审步骤
    - [ ] 优化点7：80+路线图缺优先级/推荐指引，建议按新手→进阶→专项分组并标注推荐度
    - [ ] 优化点8：本地化/多语言支持有限，建议节点Markdown设计成可i18n抽取
    - [ ] 优化点9：孤儿清理规则可解释性不足，建议删除前生成diff报告开PR人工确认而非直接删
    - [ ] 优化点10：close-feedback-pr自动关闭缺引导，建议附"请改用issue/编辑器"模板与理由
