- [ ] 一、项目回顾
  - [ ] 1. 一句话结论：opinionated Python工具shortlist（非catalog），每use case硬上限5（3首选+2挑战者），以PyPI下载量而非GitHub star为采信信号
  - [ ] 2. 场景问题（≤3个）
    - [ ] 做技术选型的Python工程师：PyPI同类库成百上千，30秒内知道事实标准是哪两三个
    - [ ] 想搜索过滤的开发者：官网awesome-python.com可搜索，自动抓GitHub star与PyPI下载量排序
    - [ ] 想提交进榜的维护者：准入规则写死（质量门槛5条/每use case上限5/一进一出替换/PyPI下载量为证）
  - [ ] 3. 组成结构（≤5项）
    - [ ] README.md ~1200行，按大类分组（AI&ML/Web/HTTP抓取/DB存储/数据科学/DevOps）再下钻子类目
    - [ ] website/ 官网源码与数据（build.py/templates/static/data/tests），把README构建成可搜索站
    - [ ] CONTRIBUTING.md 详尽编辑治理规则
    - [ ] Makefile + pyproject.toml/uv.lock（uv管理依赖）
    - [ ] docs/ + DESIGN.md/CONTEXT.md/AGENTS.md/CLAUDE.md 设计与上下文文档
  - [ ] 4. 技术组件（≤5项）
    - [ ] uv包管理 + ruff(lint/format) + ty(类型检查) + pytest(测试)
    - [ ] Makefile：fetch_github_stars / fetch_pypi_downloads(经clickpy) / build / preview
    - [ ] CI：.github/workflows/ci.yml（uv sync→pytest→build website）+ deploy-website.yml
    - [ ] 条目schema：`- [pypi-name](github链接) - 句号结尾描述`，显示名即PyPI包名可直接pip install
    - [ ] 编辑治理：质量门槛5条全满足 + 3+2双层推荐 + 一进一出替换 + 双重收录一致性

- [ ] 二、知识沉淀
  - [ ] 1. 前10优越点（第1组：定位与分类法）
    - [ ] 优越点1：shortlist而非catalog的定位克制，每use case硬上限5，用上限倒逼取舍对抗awesome清单膨胀
    - [ ] 优越点2：use case驱动分类法，以读者要完成的"任务"为分类单位，直接对接选型心智
    - [ ] 优越点3：3首选+2挑战者双层推荐模型，既给成熟默认项又留上升期新项目位置
    - [ ] 优越点4：以PyPI下载量而非GitHub star为采信信号（star可刷、与实际使用脱钩），并修正刷量失真
    - [ ] 优越点5："一进一出"替换机制，满员后须指名替换谁并论证更优，控制总量避免只增不腐
  - [ ] 1. 前10优越点（第2组：工程化与一致性）
    - [ ] 优越点6：可搜索官网+自动活跃度数据（fetch stars/PyPI下载量），静态Markdown升级成带信号站点
    - [ ] 优越点7：完整工程化质量门禁（pytest/ruff/ty/build），连"清单"都当软件工程CI守门
    - [ ] 优越点8：双重收录一致性规则，同一工具跨类目各占独立槽位、描述改动同commit同步所有副本
    - [ ] 优越点9：PyPI包名即显示名，减少"点进去才知道pip装哪个"的摩擦，所见即可装
    - [ ] 优越点10：与子awesome-*清单分工，主表负责果断推荐、全量交给专项清单，精简与全量分层
  - [ ] 2. 前10优化点（第1组：治理与信号透明）
    - [ ] 优化点1：编辑判断集中于维护者个人（maintainer's decision is final），建议引入候补编辑/轮换、常见裁决规则化
    - [ ] 优化点2：每条目缺版本/许可证/最后更新字段，建议网站侧补license/Python版本/最近release
    - [ ] 优化点3：下载量信号未公开可视化，建议网站公开每条目下载量曲线与抓取日期，让准入争议基于公开数据
    - [ ] 优化点4：分类粒度随生态变化，建议定期复盘AI agents/MCP等新use case是否需独立成类
    - [ ] 优化点5：无迁移/弃用提示，建议对"近12月无提交仍在榜"条目自动标记/提醒
  - [ ] 2. 前10优化点（第2组：易用与质量）
    - [ ] 优化点6：本地化缺失，建议官网加i18n至少中/日文关键界面
    - [ ] 优化点7：条目对比维度单一，建议同类候选加简短对比表（语法/性能/生态）
    - [ ] 优化点8：CI未做链接存活/去重校验，建议加links_checker与重复条目检测
    - [ ] 优化点9：挑战者上升路径不透明，建议定义定期复审节奏把成熟挑战者升级为obvious
    - [ ] 优化点10：CONTRIBUTING规则详尽偏长，建议提供PR自查checklist模板降低无效PR比例
