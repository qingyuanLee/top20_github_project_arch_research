- [ ] 一、项目回顾
  - [ ] 1. 一句话结论
    - [ ] 编码Agent的工程方法论框架，用"技能+强制门控"把TDD/计划/子Agent审查写成Agent启动必检的硬约束
    - [ ] 注意：stars疑似异常（约11个月冲288k★），本归档以架构机制为准，不以star数证明质量
  - [ ] 2. 场景问题（3个）
    - [ ] 裸Agent拿到需求就乱写：SessionStart注入bootstrap，识别"要构建东西"自动触发brainstorming，批准后才允许实现
    - [ ] 多套编码Agent工具链无法复用方法论：核心skills/单一来源，13+harness各配一份适配壳，一行命令安装
    - [ ] 长任务无人值守Agent偏离计划：writing-plans拆成2-5分钟小任务，subagent-driven-development派新子Agent两段审查
  - [ ] 3. 组成结构（5项）
    - [ ] skills/核心技能库：14个技能，每个含SKILL.md（frontmatter强触发description+HARD-GATE块）
    - [ ] hooks/运行时引导：hooks.json声明SessionStart钩子，matcher=startup|clear|compact同步注入bootstrap
    - [ ] 多harness适配目录：.claude-plugin/.codex-plugin/.cursor-plugin/.devin-plugin等十余个，核心零改动
    - [ ] 多Agent入口文件：AGENTS.md/CLAUDE.md/GEMINI.md面向不同运行时
    - [ ] 工程文件：package.json锁version 6.3.0，pre-commit配置，tests/基础设施测试
  - [ ] 4. 技术组件（5项）
    - [ ] 无传统后端，主语言Shell（run-hook.cmd/session-start脚本），本质是技能+钩子+多harness清单分发包
    - [ ] 14技能覆盖：brainstorming/writing-plans/executing-plans/TDD/systematic-debugging/subagent-driven-development等
    - [ ] 三路径任务分级：Spike只要答案/Bounded短设计/Full才写spec，仪式感随任务伸缩、审批门永不伸缩
    - [ ] 质量门禁：pre-commit本地检查+tests/基础设施测试+独立superpowers-evals行为测试
    - [ ] 分发渠道：Anthropic/Codex/Grok官方市场+自建obra/superpowers-marketplace，MIT开源
  - [ ] 5. 验证：stars=288183（疑似异常，仅作记录）
- [ ] 二、知识沉淀
  - [ ] 1. 前10优越点
    - [ ] 第1组（门控与复用）
      - [ ] 优越1：用"技能+强制门控"把工程纪律写成可执行Agent约束，HARD-GATE阻断式流程而非建议式prompt
      - [ ] 优越2：一次编写13+harness复用的适配层架构，新增harness只加清单/启动脚本，核心零改动
      - [ ] 优越3：SessionStart钩子挂compact事件，解决长会话压缩后技能"失忆"，每次记忆截断后自动重新自检
      - [ ] 优越4：任务规模自适应三路径设计，Spike/Bounded/Full分级，避免改个标点也要写设计文档
      - [ ] 优越5：子Agent两段式审查流水线，先审spec符合性再审代码质量，新上下文子Agent消除自评盲点
    - [ ] 第2组（纪律与可持续）
      - [ ] 优越6：TDD做成不可绕过的RED-GREEN-REFACTOR循环，并要求删掉先于测试写出的代码
      - [ ] 优越7：元技能writing-skills教Agent自己长新技能，跨harness兼容作为合并门槛
      - [ ] 优越8：与Git worktree深度绑定，隔离工作区+干净测试基线，多任务/多子Agent互不踩踏
      - [ ] 优越9：显式遥测opt-out，只统计版本号不收集项目/prompt，尊重宿主Agent隐私开关
      - [ ] 优越10：商业可持续双轨，核心MIT开源换增长，企业服务（sales@primeradiant.com）变现换维护
  - [ ] 2. 前10优化点
    - [ ] 第1组（可信度与一致性）
      - [ ] 优化1：star数异常暴涨信噪比风险，应以实际安装量/evals通过率替代GitHub star作主指标
      - [ ] 优化2：跨harness一致性靠人工纪律，缺自动回归矩阵测试，Hermes已暴露无post-compaction hook丢bootstrap
      - [ ] 优化3：技能触发依赖自然语言description，缺结构化触发条件schema，存在误触发/漏触发
      - [ ] 优化4：缺按项目/团队裁剪技能集机制，装上即全套14个，无法按成熟度开关
      - [ ] 优化5：eval体系独立于主仓需另clone superpowers-evals，新贡献者上手成本高
    - [ ] 第2组（体验与成本）
      - [ ] 优化6：HARD-GATE粒度未按任务类型分级，Spike纯探索也走完整分类+对话略重
      - [ ] 优化7：子Agent审查token消耗未透明化，长autonomous任务用户无法预估账单
      - [ ] 优化8：遥测仅统计版本，无法反哺技能质量改进优先级
      - [ ] 优化9：缺新手"5分钟最小可用示例"walkthrough，README从13种安装命令开始信息量大
      - [ ] 优化10：AGENTS.md/CLAUDE.md/GEMINI.md多入口文件存在漂移风险，应单一源+发布时生成
