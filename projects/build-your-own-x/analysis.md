- [ ] 一、项目回顾
  - [ ] 1. 一句话结论：CodeCrafters 旗下"从零手写一个工具"的纯 README 教程聚合仓库，单文件即产品
  - [ ] 2. 场景问题
    - [ ] 场景一：初中级程序员想从"会用框架"到"懂原理"——教程只教用工具、官方源码太大手，选一篇 Python 写 Git 逐步实现 commit/push
    - [ ] 场景二：准备面试/夯实 CS 基础的学生求职者——八股缺动手体感，按 Database/OS 分类边读边敲
    - [ ] 场景三：CodeCrafters 付费产品的流量入口——顶部 banner 与"now maintained by CodeCrafters"把免费列表导流到付费挑战
  - [ ] 3. 组成结构
    - [ ] README.md：banner + 29 个 Build-your-own 分类 + 教程链接列表（全部内容所在）
    - [ ] ISSUE_TEMPLATE.md：贡献提交模板（语言/标题/URL/分类勾选）
    - [ ] codecrafters-banner.png：顶部宣传横幅
    - [ ] .gitattributes：确保被 GitHub 识别为 Markdown
    - [ ] 无源码、无 CI、无 package.json，纯内容聚合型 README
  - [ ] 4. 技术组件
    - [ ] Markdown + GitHub Flavored Markdown
    - [ ] GitHub 仓库本身作分发平台
    - [ ] ISSUE_TEMPLATE.md 结构化贡献入口
    - [ ] CC0 1.0 License 内容无版权
    - [ ] 外部教程托管（博客/Medium/YouTube 等），仓库仅存链接
  - [ ] 5. 验证：stars=547926，来源=GitHub API，排名 #1
- [ ] 二、知识沉淀
  - [ ] 1. 前 10 结构性优越点
    - [ ] 组 1（1-5）
      - [ ] 优越点1：单文件 README 即全部产品，访问成本为零
        - [ ] 点开即读，无需安装/构建；比 clone 运行的教程仓库摩擦更低
      - [ ] 优越点2：29 个分类覆盖计算机科学全谱系
        - [ ] 从 Web Server 到 OS/Processor 再到 AI Model/LLM/RAG，全栈好奇心一份满足
      - [ ] 优越点3：每条目同标"语言+标题"，双维度检索
        - [ ] 统一 `**语言**: 标题`，可按熟悉语言过滤，降低语言不熟的放弃率
      - [ ] 优越点4：Feynman 名言定调，主题叙事统一
        - [ ] "What I cannot create, I do not understand"，差异化"亲手造"定位
      - [ ] 优越点5：贡献模板把提交门槛结构化
        - [ ] ISSUE_TEMPLATE 强制四字段 + 25 分类勾选，审核成本远低于自由文本
    - [ ] 组 2（6-10）
      - [ ] 优越点6：CC0 协议最大化传播自由度
        - [ ] 连署名都不要，第三方可自由转载，间接放大曝光
      - [ ] 优越点7：与 CodeCrafters 付费产品形成免费/付费漏斗
        - [ ] 免费列表做 SEO 与品牌，banner 导流交互式付费挑战，有变现闭环
      - [ ] 优越点8：无代码依赖，仓库长期可维护
        - [ ] 无依赖腐化/构建失败/breaking change，维护者只做"加链接"
      - [ ] 优越点9：分类锚点目录直接可跳转
        - [ ] 长约 500 行不迷路，锚点与 #### 标题严格对应，移动端友好
      - [ ] 优越点10：随技术浪潮自更新（LLM 等新类目）
        - [ ] 社区 PR 快速纳入 LLM/RAG/Diffusion 新教程，保持时效
  - [ ] 2. 前 10 优化增强点
    - [ ] 组 1（1-5）
      - [ ] 优化点1：死链无自动检测
        - [ ] 无 CI，数百外链随时间失效；建议加 GitHub Actions 每周跑 lychee 巡检
      - [ ] 优化点2：条目无分级与质量标签
        - [ ] 经典与水文并列；建议对官方/高频条目加 ⭐ 或置顶首推
      - [ ] 优化点3：无难度/前置知识标注
        - [ ] 不区分周末项目与三月系列；建议加 beginner/intermediate/advanced + 预计时长
      - [ ] 优化点4：分类间无"学习路径"串联
        - [ ] 29 分类平铺；建议加 Shell→Git→Database→OS→Compiler 推荐路线
      - [ ] 优化点5：无搜索功能
        - [ ] 500 行只能 Ctrl+F；建议顶部加 GitHub 搜索链接或 Pages+lunr 静态搜索
    - [ ] 组 2（6-10）
      - [ ] 优化点6：模板分类列表与正文可能漂移
        - [ ] 两处手工维护；建议从单一 JSON/YAML 源自动生成目录与模板 checkbox
      - [ ] 优化点7：视频/文字混排但无格式筛选
        - [ ] [video]/[pdf] 混排；建议统一加 [book]/[video]/[article] 标签做视图
      - [ ] 优化点8：无社区评价/互动数据沉淀
        - [ ] 看不到跟做人数；建议开 Discussion 区收集反馈、淘汰劣质条目
      - [ ] 优化点9：语言维度无独立索引
        - [ ] 语言写在条目里；建议加"按语言反查"总表附录
      - [ ] 优化点10：与商业产品边界可更清晰
        - [ ] 未区分社区教程与 CodeCrafters 付费挑战；建议对关联内容注明，保中立
