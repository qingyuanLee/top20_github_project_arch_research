- [ ] 一、项目回顾
  - [ ] 1. 一句话结论：自托管多渠道 AI 网关，把个人 AI 助手接到用户已有的20+聊天渠道，同一二进制靠配置切换个人/团队，模型与数据不出本地
  - [ ] 2. 场景问题（≤3个）
    - [ ] 把个人AI助手接进日常IM群（WhatsApp/Telegram/Slack/Discord/iMessage等），不用单开App
    - [ ] 个人版与团队共享版共用一套部署，仅靠配置区分单/多用户
    - [ ] 模型可插拔（Claude/Codex/本地模型），state/memory/credentials留在自己硬件
  - [ ] 3. 组成结构（≤5项）
    - [ ] pnpm workspace monorepo（根CLI入口 openclaw.mjs + 多tsconfig分包）
    - [ ] src/ 主源码110+模块目录（gateway/channels/agents/llm/memory/mcp/plugins）
    - [ ] packages/ 23个内部包（gateway-protocol/agent-core/llm-core/plugin-sdk等）
    - [ ] crates/ Rust两个crate（gateway-client/node-host）
    - [ ] apps/ 多端原生壳（android/ios/macos/linux/mobile）+ extensions/渠道实现 + ui/控制台
  - [ ] 4. 技术组件（≤5项）
    - [ ] TypeScript + Node24/Hono + Zod + tsdown(rolldown)
    - [ ] SQLite+Kysely 会话持久化 + LanceDB 向量记忆
    - [ ] Vitest单测 + 数百个docker e2e + live模型测试 + 性能budget
    - [ ] Rust crate 承担性能敏感面（FFI调用）
    - [ ] 供应链安全工程化：7天依赖冷却(minimumReleaseAge=10080)+patch/override钉死CVE传递依赖
  - [ ] 5. 验证：stars=390022（#6，主语言TypeScript，B类；star增速疑似网红冲量，结论不依赖排名）
- [ ] 二、知识沉淀
  - [ ] 1. 前10优越点（第1组：架构解耦与多端一致）
    - [ ] 优越点1：pnpm workspace多包架构，协议/模型/记忆/插件契约全抽成23个独立版本化包，src/apps/extensions复用同一内核
    - [ ] 优越点2：Gateway唯一本地控制平面，CLI/TUI/Control UI三前端共享，单/团队仅靠配置切换
    - [ ] 优越点3：渠道插件化+20+渠道矩阵，新增IM=新extension不改内核，有契约测试兜底
    - [ ] 优越点4：模型后端可插拔provider抽象层（ai/llm-core/model-catalog），换harness不动其他部分
    - [ ] 优越点5：Rust原生crate承担网关客户端与节点宿主，长连接/高并发下性能与内存安全
  - [ ] 1. 前10优越点（第2组：工程化与治理）
    - [ ] 优越点6：供应链安全制度化——新包冷却7天再用，已知CVE传递依赖逐条钉死且排除项带移除日期
    - [ ] 优越点7：超强质量门禁——架构/循环依赖(madge)/死代码(knip)/协议跨端生成(Kotlin/Swift)全做成CI硬规则
    - [ ] 优越点8：测试金字塔完整——单元/docker e2e/live模型/性能预算分层隔离，onboarding等用户旅程都做成docker测试
    - [ ] 优越点9：隐私优先默认——trusted gateway/untrusted execution/deterministic policy，凭据不出本地、遥测opt-in
    - [ ] 优越点10：OpenClaw基金会501(c)(3)治理（OpenAI是捐赠方非所有者）+ npm/Docker/Fly/Render/原生移动端全部署面
  - [ ] 2. 前10优化点（第1组：工程债与外部信号）
    - [ ] 优化点1：package.json脚本近500个规模过大，新人理解成本高，建议拆成内部CLI子命令
    - [ ] 优化点2：override/patch名单冗长且带临时到期日（多处已过期），建议CI加"到期未清理即失败"
    - [ ] 优化点3：B类却以聊天机器人网关形态爆红、star量级异常，需持续跟踪commit活跃度/真实下载量区分质量与热度
    - [ ] 优化点4：跨端协议代码生成覆盖面仍有限，大量tmp临时lint手工维护，建议把更多契约纳入自动生成
    - [ ] 优化点5：Rust与TS的FFI边界需补ABI版本契约与崩溃恢复测试，防原生层崩溃拖垮Gateway
  - [ ] 2. 前10优化点（第2组：安全/可移植/生态）
    - [ ] 优化点6：记忆/向量存储绑死LanceDB+SQLite本地格式，建议定义导出/导入schema支持跨设备迁移
    - [ ] 优化点7：DM渠道默认按未知发送者配对，onboarding应强制提示风险并提供"仅允许已审批联系人"一键收紧
    - [ ] 优化点8：文档与代码双源同步脚本多，建议配置schema/渠道目录/CLI命令直接从源码生成到文档站
    - [ ] 优化点9：性能基线可观测闭环不足，建议把perf budget与生产OTel/Prometheus指标对齐
    - [ ] 优化点10：ClawHub插件生态缺质量门槛，建议为第三方插件建签名/权限声明/沙箱分级/恶意行为自动扫描
