  - [ ] 1. 一句话结论
    - [ ] Linux 用「arch 硬件抽象层 → kernel/mm/fs/net 核心子系统层 → drivers 设备驱动层」的三层结构，同一套核心代码经 arch 抽象支撑 22 种架构，Kconfig 编译期裁剪
  - [ ] 2. 场景问题（3 个，≤5）
    - [ ] 场景一：编写新硬件驱动的驱动开发者/硬件厂商——硬件千差万别，在 drivers/ 对应类别按子系统框架写驱动，复用 bus/core/irq/dma 抽象
    - [ ] 场景二：为发行版裁剪/配置内核的系统工程师——内核选项以万计，通过顶层 Makefile/Kconfig + make menuconfig 选择子系统
    - [ ] 场景三：研究内核机制的学术/安全研究者——沿 kernel/（调度/cgroup/bpf）、mm/、net/、init/ 目录阅读，配合 Documentation/ 设计文档
  - [ ] 3. 组成结构（5 项，≤5，突出子系统分层）
    - [ ] 体系结构层 arch/：实查 22 个架构（x86/arm64/riscv/powerpc/s390/loongarch 等），每架构含 Kconfig/Makefile
    - [ ] 核心子系统层：kernel/（调度、cgroup、bpf、audit）、mm/（内存）、fs/（VFS + 数十种 FS）、net/（网络栈）、ipc/security/crypto
    - [ ] 设备驱动层 drivers/：按类别细分 accel/acpi/ata/bluetooth/block/char/clk/cpufreq/usb/gpio 等，复用通用框架
    - [ ] 构建与配置顶层：Makefile 总入口、Kconfig 全局配置树、Kbuild/、.clang-format、.rustfmt.toml
    - [ ] 治理层：MAINTAINERS 文件列每个子系统维护者与邮件列表、LICENSES/（GPLv2）、Documentation/process/ 贡献流程
  - [ ] 4. 技术组件（5 项，≤5）
    - [ ] 主语言：C（自实现内核 libc），新增 rust/ 与 .rustfmt.toml（Rust for Linux）
    - [ ] 构建体系：Kbuild/Makefile + Kconfig 配置树，make menuconfig，产物 vmlinux/zImage
    - [ ] 核心数据流：boot → arch/<arch>/ 启动 → init/main.c(start_kernel) → 调度/mm/子系统初始化 → syscall 入 kernel/ → 对应子系统 → drivers 操作硬件
    - [ ] 维护流：patch → 邮件列表 lore.kernel.org → 子系统 maintainer review（依 MAINTAINERS）→ linux-next → torvalds/linux 主线
    - [ ] 工具链：Coccinelle 语义补丁批量 API 迁移、.mailmap 统一署名、.git-blame-ignore-revs

- [ ] 二、知识沉淀（TL;DR：分层子系统 + Kconfig 裁剪 + MAINTAINERS 分布式治理是核心优势，构建体验与新贡献者入门是主要短板）
  - [ ] 1. 前 10 优越点（第 1 组 1–5，突出子系统分层）
    - [ ] 优越点 1：宏内核 + 统一设备模型的极致可移植性——arch/ 实查 22 种架构，一套核心子系统代码覆盖从嵌入式到超算
    - [ ] 优越点 2：Kconfig/Kbuild 配置驱动的可裁剪构建——编译期按 .config 裁剪，无死代码、体积可控
    - [ ] 优越点 3：分层清晰的子系统职责边界——kernel/mm/net/fs/ipc/security/crypto/drivers 顶层分目录，各有 maintainer，千万行代码靠目录边界并行开发少冲突
    - [ ] 优越点 4：MAINTAINERS 文件驱动的分布式治理——每个子系统有明确维护者与邮件列表，patch 路由自动化
    - [ ] 优越点 5：drivers/ 按类别细分的复用框架——每类外设复用 bus/core/dma/irq 框架，新驱动只填回调，硬件适配成本逐代下降
  - [ ] 1. 前 10 优越点（第 2 组 6–10）
    - [ ] 优越点 6：文件系统层 VFS 抽象 + 多 FS 实现——VFS 统一接口，挂接 9p/afs/autofs/befs/binfmt_elf 等数十种，广度业界无可比拟
    - [ ] 优越点 7：eBPF 与可观测性的内核级扩展——运行时安全可编程扩展内核行为而不改主线，成为云原生数据面标准
    - [ ] 优越点 8：长期 ABI 稳定性承诺——用户态二进制与驱动 ABI 长期兼容，商业厂商可稳定依赖
    - [ ] 优越点 9：引入 Rust 的现代化演进——保持 C 主体同时在驱动层提供内存安全，成熟内核中首个大规模引入
    - [ ] 优越点 10：Coccinelle/静态分析驱动的大规模重构——用语义补丁做跨子系统批量 API 迁移，千万行级演进靠工具不靠手工
  - [ ] 2. 前 10 优化点（第 1 组 1–5）
    - [ ] 优化点 1：构建时间与增量编译体验——深化 make -j 并行、sccache/缓存、更细粒度增量，降 CI 成本
    - [ ] 优化点 2：文档与代码的对齐——将关键 Kconfig 项与 API 注释自动生成文档
    - [ ] 优化点 3：Rust 驱动生态成熟度——扩充 Rust 驱动 API 覆盖、提供更多样例驱动
    - [ ] 优化点 4：编译 warning 与 sanitizer 覆盖——默认开更多 sanitizer/CI 门禁，逐步清零历史 warning
    - [ ] 优化点 5：子系统间耦合的显式化——深化头文件分层与子系统间接口收敛，控制跨子系统改动影响面
  - [ ] 2. 前 10 优化点（第 2 组 6–10）
    - [ ] 优化点 6：新贡献者入门路径——提供结构化 good first issues 地图与模块索引
    - [ ] 优化点 7：配置选项的治理——定期标记废弃 Kconfig 项、提供推荐配置 profile，减少僵尸配置
    - [ ] 优化点 8：编译器版本与工具链演进——明确最低编译器要求并自动化测试矩阵
    - [ ] 优化点 9：安全加固的默认化——在默认/发行版配置中纳入更多 CFI/hardening
    - [ ] 优化点 10：AI 编码助手的架构索引——为子系统提供架构地图/AGENTS.md，降低 AI 生成 patch 的理解成本
