- [ ] 一、项目回顾
  - [ ] 1. 一句话结论：免费交互式全栈学习平台，pnpm+Turborepo 现代 Monorepo（client/api/curriculum 三端同构 TypeScript）
  - [ ] 2. 场景问题
    - [ ] 场景一：零预算想转行做开发的成年人——6 张免费证书（RWD/JS/前端库/Python/DB/后端API），浏览器里写代码即时判定
    - [ ] 场景二：想做第一个开源 PR 的新贡献者——first-timers-only 徽章 + good first issue，本地 pnpm develop 起 client+api
    - [ ] 场景三：自托管/二次开发学习平台的教育团队——BSD-3 可商用，Monorepo 拆 client/api/curriculum 三子包改题即可
    - [ ] 场景四：捐赠人/非营利资助方——501(c)(3) 慈善，工程透明可审计
  - [ ] 3. 组成结构
    - [ ] client/：Gatsby 5 + React 18 前端（课程页/编辑器/证书/博客）
    - [ ] api/：Fastify 5 后端（认证/判定/证书/Stripe 支付）
    - [ ] curriculum/：题目源文件 + schema + i18n-curriculum 多语言
    - [ ] packages/：challenge-builder、challenge-linter、eslint-config、shared
    - [ ] tools/ + e2e/（Playwright）+ docker/ + .github/ + .husky/
  - [ ] 4. 技术组件
    - [ ] 包管理编排：pnpm 10.33 + Turborepo 2.10（远程缓存）+ Node>=24
    - [ ] 前端：React 18 + Redux Toolkit/saga/observable + Monaco + Sandpack + xterm
    - [ ] 后端：Fastify 5 + Prisma 6 + MongoDB + TypeBox/Joi/AJV 校验
    - [ ] 工程门禁：husky+lint-staged、knip 死代码、stylelint、renovate 供应链（minimumReleaseAge 7天）
    - [ ] 外部依赖：Crowdin 翻译、Stripe 支付、Algolia 搜索、Sentry 监控、GrowthBook A/B

- [ ] 二、知识沉淀
  - [ ] 1. 前 10 结构性优越点
    - [ ] 组 1（1-5）
      - [ ] 优越点1：pnpm + Turborepo 的现代 Monorepo 架构
        - [ ] 12 个 workspace 包共享类型与 ESLint，turbo 增量构建+远程缓存，CI 分钟级
      - [ ] 优越点2：课程内容与应用代码物理分离
        - [ ] 题目 markdown/yml 经 challenge-builder 编译成 curriculum.json，写题不用懂 React
      - [ ] 优越点3：前后端同构 TypeScript + 共享包
        - [ ] packages/shared 一份维护类型/工具函数，跨包改字段编译期报错
      - [ ] 优越点4：Fastify + Prisma + TypeBox 类型安全后端
        - [ ] TypeBox 运行时与编译时共享 schema，校验/响应/Swagger 三者同源
      - [ ] 优越点5：浏览器内沙箱执行（Sandpack + Monaco）
        - [ ] 写完代码浏览器即跑，无需本地装 Node，VS Code 级编辑器体验
    - [ ] 组 2（6-10）
      - [ ] 优越点6：企业级工程质量门禁
        - [ ] 类型/lint/死代码/stylelint 全自动硬门禁（--max-warnings 0），人工只看业务逻辑
      - [ ] 优越点7：依赖供应链安全工程
        - [ ] minimumReleaseAge 7 天观察期 + postinstall 白名单 + renovate 自动升级，防供应链攻击
      - [ ] 优越点8：E2E 测试独立成包（Playwright）
        - [ ] e2e 独立 workspace 不污染单测，跨浏览器测真实用户流程
      - [ ] 优越点9：数据库 seed 与开发体验脚本化
        - [ ] 一整套 seed 脚本，clone 后 pnpm seed 即得假用户/假进度/假证书
      - [ ] 优越点10：多语言课程 + Crowdin 同步管线
        - [ ] i18n-curriculum 多语言 + tools/crowdin 自动同步，覆盖全球非英语用户
  - [ ] 2. 前 10 优化增强点
    - [ ] 组 1（1-5）
      - [ ] 优化点1：Gatsby 5 技术栈老化风险
        - [ ] Gatsby 进维护模式、插件生态停更；建议评估迁 Next.js 15 App Router
      - [ ] 优化点2：状态管理三框架并存
        - [ ] redux/saga/observable 三套副作用模型并存；建议逐步收敛到单一方案
      - [ ] 优化点3：MongoDB + Prisma 组合的灵活性折损
        - [ ] Prisma 对 MongoDB 支持不如 PG 成熟；建议评估迁 PostgreSQL 或 Mongoose
      - [ ] 优化点4：Node >=24 的高门槛
        - [ ] 2025 新引擎对老机器不友好；建议放宽到 Node 20 LTS 或 devcontainer 标准化
      - [ ] 优化点5：课程内容编译流程可观测性不足
        - [ ] 无 curriculum.json 大小/题目数/语言覆盖率监控；建议 CI 加可视化报告
    - [ ] 组 2（6-10）
      - [ ] 优化点6：E2E 测试未与 preview 环境联动
        - [ ] Playwright 本地跑，PR preview 不自动触发；建议接 Vercel preview + CI 跑关键路径
      - [ ] 优化点7：Monaco + Sandpack bundle 体积大
        - [ ] 全量打进 client，构建吃 7GB 内存；建议 worker 按需加载 + 路由级 code splitting
      - [ ] 优化点8：多语言翻译自动化程度低
        - [ ] Crowdin→仓库合并仍人工、无质量校验；建议接术语一致性/占位符/长度 CI
      - [ ] 优化点9：无公开的 API 文档站点
        - [ ] Swagger 生成但未独立部署；建议把 /documentation 暴露为公开 API 文档
      - [ ] 优化点10：curriculum 题目 schema 演进无版本化
        - [ ] v6→v9 无迁移工具；建议加 version 字段 + 批量升级脚本
