- [ ] 一、项目回顾（TL;DR：一套把 AI 编码工作流固化下来的「agent harness 操作系统」配置包）
  - [ ] 1. 一句话结论
    - [ ] ECC 不是运行时应用，而是配置包：一次安装把 plan→test→implement→review→verify→remember→improve 固化到 7+ 种 AI 编码工具
  - [ ] 2. 场景问题（3 个，≤5）
    - [ ] 场景一：重度使用 Claude Code/Codex/Cursor 的工程师——每次新会话都要重写工作流提示词，重复劳动靠人肉
    - [ ] 场景二：团队内多套 harness 并行的 Tech Lead——各工具配置不互通，技能/规则/记忆无法跨工具复用
    - [ ] 场景三：在私有代码仓跑 agent 的安全敏感团队——担心 prompt 注入、恶意 hook、泄露 secret
  - [ ] 3. 组成结构（5 项，≤5）

    - [ ] 插件元数据：.claude-plugin/ 下 plugin.json、marketplace.json、PLUGIN_SCHEMA_NOTES.md
    - [ ] 工程治理：.github CI、.coderabbit.yaml 自动 review、gitleaks、markdownlint、prettier
    - [ ] 能力清单：68 agents / 292 skills / 94 legacy command shim + hooks/rules/memory
    - [ ] 安全闭环：内置 AgentShield 扫描 prompts/hooks/MCP/permissions/secrets/agent 文件

  - [ ] 1. 前 10 优越点（第 1 组 1–5）

    - [ ] 优越点 2：把工作流固化为插件而非 prompt 片段——hooks/runtime 强制执行，装一次即生效
    - [ ] 优越点 3：能力分层 SKU 化清单——68/292/94 透明列项，用户按需勾选，降低理解成本
    - [ ] 优越点 4：内置 AgentShield 安全扫描——把新兴的 agent 供应链风险做成一等公民组件
    - [ ] 优越点 5：幂等且多包管理器兼容的安装向导——先盘点再改动 + 版本 pin + 可重复执行，破坏面小
