- [ ] 一、项目回顾（TL;DR：自带闭环学习的云端 AI agent，单一网关接多 IM，模型可插拔，原生 cron 调度，产品同时是训练数据采集器）
  - [ ] 1. 一句话结论
    - [ ] Hermes 是跑在 $5 VPS 上的 24/7 自改进 agent：gateway 统一接 Telegram/Discord 等，agent 运行时多 provider 可切换，闭环「任务→自创技能→记忆→召回」，外加 cron 定时与 subagent 并行
  - [ ] 2. 场景问题（3 个，≤5）
    - [ ] 场景一：想把 agent 跑云端、用手机随时聊的个人开发者——本地 agent 一关电脑就停；在 VPS 装完 hermes gateway，从 Telegram 发消息让云端干活
    - [ ] 场景二：要「越用越懂你」的长期个人助理——新对话从零开始不记得偏好；靠自创建技能、FTS5 会话搜索、Honcho 用户建模
    - [ ] 场景三：要定时自动化与并行子任务的运维/研究用户——通用聊天 agent 不会定时、不能并行；用 cron/scheduler.py 建任务、spawn 隔离 subagent 并行、结果投到 IM
  - [ ] 3. 组成结构（5 项，≤5）
    - [ ] agent/（核心运行时）：anthropic/bedrock/azure_identity 等 provider adapter + agent_init/runtime_helpers/api_request_hooks/async_utils/background_review/billing_usage
    - [ ] acp_adapter/（标准协议）：server/session/tools/permissions/edit_approval/provenance/model_catalog/auth——把 agent 暴露为标准 ACP 服务
    - [ ] cron/（定时子系统）：scheduler/jobs/executions/occurrences/delivery_queue/bot_chat_delivery/monitor/incidents/lifecycle_guard
    - [ ] apps/ 与入口：bootstrap-installer、desktop、shared；cli.py、run_agent.py、Dockerfile、docker-compose（含 Windows 版）
    - [ ] 学习闭环与治理：FTS5 记忆 + Honcho 用户建模 + 技能自创建；README 多语、COMPAT_MANIFEST、SECURITY.md、.coderabbit.yaml
  - [ ] 4. 技术组件（5 项，≤5）
    - [ ] 语言/环境：Python 3.11（uv 管理）+ Node.js（桌面端）
    - [ ] 模型无关：Nous Portal/OpenRouter/OpenAI/Bedrock/Azure/自建 endpoint，hermes model 零代码切换
    - [ ] 部署与运行环境：Docker/Compose；7 种终端后端 local/Docker/SSH/Singularity/Modal/Daytona/Vercel Sandbox，闲置休眠

    - [ ] 研究闭环：batch_runner.py 批量生成轨迹 → 压缩 → 训练下一代工具调用模型（产品即数据采集器）

  - [ ] 1. 前 10 优越点（第 1 组 1–5）
    - [ ] 优越点 1：内置闭环学习（自改进 agent）——任务→自动创建技能→使用中改进→记忆沉淀→跨会话召回，区别于无状态对话
    - [ ] 优越点 2：模型/Provider 完全可插拔——多 provider adapter，hermes model 切换零代码、无锁定
    - [ ] 优越点 3：单一网关多平台消息接入——一个进程统一 6 个 IM + CLI，跨平台会话连续
    - [ ] 优越点 4：原生 cron 定时自动化子系统——自然语言定时任务 + 投递 + monitor + incidents，无人值守运行
    - [ ] 优越点 5：7 种终端后端与 serverless 休眠——从 $5 VPS 到 GPU 集群到 serverless，成本随用随付
  - [ ] 1. 前 10 优越点（第 2 组 6–10）
    - [ ] 优越点 6：ACP 标准协议适配层——暴露为标准 Agent Client Protocol 服务，天然支持权限审批与可追溯
    - [ ] 优越点 7：产品即研究数据闭环——用户使用轨迹反哺下一代工具调用模型训练
    - [ ] 优越点 8：Windows 原生 + 隔离便携工具链——PowerShell 一键装、自带 MinGit 到 %LOCALAPPDATA%，无需 WSL、不污染系统 Git
    - [ ] 优越点 9：subagent 并行与 RPC 工具脚本——多工作流并行，多步流水线压成零上下文成本回合
    - [ ] 优越点 10：多语言 README 与 COMPAT_MANIFEST 治理——用兼容清单显式声明能力边界，自动 PR review
  - [ ] 2. 前 10 优化点（第 1 组 1–5）
    - [ ] 优化点 1：star 数与产品成熟度的可信度——公开下载量/活跃用户/轨迹数等多维指标
    - [ ] 优化点 2：provider 适配层的收敛——抽象统一 provider 接口，新 provider 只填差异
    - [ ] 优化点 3：学习闭环的可控性——提供技能审核与开关，避免自动写入不可信技能
    - [ ] 优化点 4：多平台网关的消息一致性——抽象平台能力矩阵，降级不可用功能
    - [ ] 优化点 5：cron 任务的可观测性——任务级日志、重试、死信队列与可视化
  - [ ] 2. 前 10 优化点（第 2 组 6–10）
